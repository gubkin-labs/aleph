# Auth and callers

Auth in Aleph is declared, not built. Each route says who may call it:
- anyone
- any signed-in user
- members of the org in its path, optionally with certain roles
- API keys with certain scopes

The core enforces that rule before the plan runs. Your plans read the caller's id, their role, and their profile fields.

Proving *who* the caller is (sessions, passwords, OAuth) is done by the runtime in front of the core, which passes the authenticated **caller** in with each request.

## Who may call

```ts
const a = app("team", { roles: ["owner", "admin", "member"], apiKeyScopes: ["members:read"] });

a.route("GET /health").auth("public");
a.route("GET /me");                                   // default: any signed-in user
a.route("GET /orgs/:orgId/projects").member("orgId");                       // any member of the org
a.route("DELETE /orgs/:orgId").member("orgId", { roles: ["owner"] });       // only owners
a.route("GET /orgs/:orgId/members").member("orgId", { apiKeyScopes: ["members:read"] }); // or an API key
```

Roles and scopes are declared on the app, so a typo in a route's roles or scopes is a validation error (and, in your editor, a type error).

| Failure | Response |
|---|---|
| Not signed in | `401 unauthorized` |
| Not a member, wrong role, or a key without the scopes | `403 forbidden` |

## Inside a plan

| | |
|---|---|
| `$.caller` | The signed-in user's id |
| `$.callerRole(orgId)` | Their role in an org, or `null` |
| `a.caller.profile.email` | A field of the caller's profile |
| `a.users.get(userId)` | Any user of the tenant, from the user directory (`null` if unknown) |

Profile fields are declared on the app:

```ts
const shop = app("shop", { profile: { email: t.string().max(200), name: t.string().max(100) } });
const OrderPaid = shop.event("orderPaid", { payload: { customerId: t.string().max(64) } });
const email = shop.integration("email", {
  provider: "email",
  operations: { send: { mode: "effect", input: { to: t.string().max(200), subject: t.string().max(200) } } },
});

shop.onEvent("receipt", OrderPaid, ($, { payload }) => {
  const customer = shop.users.get(payload.customerId);
  email.send("send", { to: customer.email.ifNull("fallback@example.com"), subject: "Thanks!" });
});
```

## In development

`aleph dev` reads the caller from headers:

| Header | Meaning |
|---|---|
| `x-aleph-user: ada` | The signed-in user |
| `x-aleph-orgs: acme=owner,beta=member` | Org memberships |
| `x-aleph-api-key: acme` and `x-aleph-api-key-scopes: members:read` | An API key for an org |
| `x-aleph-profile: {"email":"ada@example.com"}` | The caller's profile |

<Note title="Not yet in the language">
Declaring sign-in methods (email and password, magic links, Google or GitHub OAuth) and org management in the manifest is planned; see the [roadmap](/docs/roadmap/). Today, whatever authenticates callers passes them to the core.
</Note>
